# أمان توثيق أصحاب المحلات

## التصميم المعتمد

يتم إنشاء طلب توثيق مستقل بدل وضع صورة الهوية أو الفيديو داخل `profiles`. يحتوي الطلب على بيانات المحل، المدينة، العنوان التفصيلي، مساري ملف الهوية والفيديو، والحالة `pending` أو `approved` أو `rejected`. لا يتم تفعيل `is_shop` ولا تظهر شارة التوثيق إلا بعد قرار الأدمن.

الموقع الإلزامي في الإصدار الحالي هو **مدينة المحل والعنوان التفصيلي**. يمكن إضافة إحداثيات GPS لاحقًا بموافقة المستخدم، لكن لا ينبغي إجبار المستخدم على مشاركة موقع دقيق إذا كان العنوان النصي كافيًا للغرض.

## حماية الملفات

يُحفظ الإثبات في bucket خاص باسم `verification-documents` وليس bucket عامًا. لا يتم تخزين رابط عام، بل مسار داخلي فقط. يستطيع صاحب الطلب رفع ملفاته الخاصة، ويستطيع الأدمن المصرح له إنشاء رابط مؤقت لمدة قصيرة للمراجعة. لا يُسمح للمستخدمين الآخرين بالقراءة أو البحث أو التنزيل.

## دور الأدمن

لا يُعرّف الأدمن من خلال قيمة يرسلها التطبيق. الصلاحية تعتمد على `app_metadata.role = admin` في Supabase Auth. يوصى عمليًا بتقسيم الصلاحيات لاحقًا إلى `super_admin` لإدارة الصلاحيات، و`verification_admin` لمراجعة الهوية، و`support_admin` للتعامل مع الطلبات دون الوصول إلى مستندات الهوية. الإصدار الحالي يستخدم دور `admin` الموثق فقط لتقليل التعقيد.

## سجل التدقيق

كل اعتماد أو رفض يُحفظ في `shop_verification_audit` مع هوية الأدمن، القرار، السبب، والوقت. يجب عدم حذف السجل عند حذف الطلب إلا وفق سياسة احتفاظ واضحة. يوصى بمراجعة صلاحية الأدمن دوريًا وتفعيل المصادقة متعددة العوامل لحسابات الإدارة.

## دورة الحالة

| الحالة | المعنى | الصلاحيات |
|---|---|---|
| `none` | لم يرسل صاحب المحل طلبًا | الحساب العادي فقط |
| `pending` | تم إرسال البيانات وتنتظر المراجعة | لا تظهر شارة التوثيق ولا يفعّل حساب المحل |
| `approved` | وافق الأدمن بعد المراجعة | يصبح الحساب محلًا موثقًا وفق الصلاحيات الممنوحة |
| `rejected` | رُفض الطلب مع سبب | يمكن للمستخدم تصحيح البيانات وإرسال طلب جديد |

ينبغي تطبيق مدة احتفاظ محدودة لمقاطع الفيديو والصور، وحذفها أو إخفاؤها بعد انتهاء الحاجة التشغيلية وفق سياسة الخصوصية والقوانين المحلية. لا يجب استخدام مستندات الهوية لأغراض تسويقية أو مشاركتها مع البائعين والعملاء.

## متطلبات التشغيل

يجب تطبيق ترحيل `20260904000500_shop_verification.sql` على مشروع Supabase قبل اختبار رفع الطلبات. كما يجب تعيين دور الأدمن يدويًا من بيئة موثوقة في `app_metadata`، وعدم وضع service-role key داخل تطبيق Flutter أو مستودع GitHub.
